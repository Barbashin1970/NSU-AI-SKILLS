# Испытания и протокол

Как из требований задания получить исполняемые испытания, и как устроить прогонщик так,
чтобы его результату верили.

## Из требований — в испытания

Одно испытание закрывает **одно общее требование** задания. Не одну функцию, не один
экран — требование, потому что принимают по требованиям.

| Испытание | Требование | Что подаётся | Что проверяется | Исход |
|---|---|---|---|---|
| И-01 | 4.1.1 адресное доведение | данные с нарушением | адресат назван, сообщение доставлено, отметка получена | ПРОЙДЕНО |
| И-02 | 4.1.2 разбор правил | правило с ошибкой в шкале | изделие отказывает целиком и называет место | ПРОЙДЕНО |
| … | | | | |
| И-07 | 4.1.7 резервная копия | команда выгрузки | архив с манифестом, восстановление из него | ЧАСТИЧНО |

Колонки «что подаётся» и «что проверяется» — существенны: без них испытание
не воспроизводится, а невоспроизводимое испытание не является доказательством.

## Прогонщик

**[практика]** Требования к прогонщику приёмочных испытаний:

1. **обращается к изделию так же, как человек** — через интерфейс, а не в обход;
2. **не имеет права отчитаться об успехе там, где возможности нет** — отсюда четыре
   исхода (см. SKILL.md);
3. **печатает ход** — чтобы за ним можно было следить на приёмке;
4. **пишет протокол в файл** с датой в имени;
5. **возвращает ненулевой код**, если хоть одно испытание не пройдено, — тогда его можно
   поставить в сборку;
6. **ничего не меняет в рабочих данных.** Испытание, портящее рабочую базу, запускают
   один раз, а потом боятся.

Скелет:

```python
ISPYTANIYA = [I01, I02, I03, I04, I05, I06, I07, I08, I09]

async def glavnoe(baza: str) -> int:
    itogi = []
    for ispytanie in ISPYTANIYA:
        itog = await ispytanie(baza)          # вернёт (kod, isxod, poyasnenie)
        pechat(itog)
        itogi.append(itog)
    zapisat_protokol(itogi)
    ne_proydeno = [i for i in itogi if i.isxod == "НЕ ПРОЙДЕНО"]
    return 1 if ne_proydeno else 0
```

## Протокол

Что в нём обязано быть:

* **дата, время, кто запускал, на каком экземпляре** (рабочий, копия данных, стенд);
* **версия изделия** — коммит либо контрольная сумма набора из описи;
* **по каждому испытанию**: номер, требование, что подавалось, что проверялось, исход,
  пояснение к исходу;
* **итог**: сколько пройдено, частично, не пройдено, показом;
* **что осталось непроверенным и почему.**

Протокол читают люди, не видевшие кода. Значит пояснение к исходу пишется словами
предметной области, а не именами функций.

**[практика]** Протокол не входит в опись состава исходного текста и не входит в поставку
как часть изделия: это вывод изделия, а не его текст. Иначе опись растёт после каждого
прогона, а контрольная сумма набора меняется после каждой приёмки.

## Испытания «показом»

Часть требований нельзя проверить программно: «интерфейс понятен оператору», «сообщение
приходит в мессенджер», «изделие работает без сети в зале». Для них:

* исход называется **ПОКАЗОМ**, а не подгоняется под «пройдено»;
* в ПМИ описан **сценарий показа**: что делает человек, что должно произойти;
* сценарий выполняется при комиссии, и результат вписывается в протокол рукой
  с подписью проводившего.

Честно названное «показом» вызывает уважение; выданное за автоматическую проверку —
разрушает доверие ко всему протоколу.

## Частые возражения комиссии и что на них отвечать

| Возражение | Чем закрывается заранее |
|---|---|
| «откуда эти числа» | каждое число в документах несёт команду (`gost-19-sverka`) |
| «а если данных нет» | изделие обязано различать «нет данных» и «норма»; испытание на это — отдельное |
| «покажите на наших данных» | прогон на копии данных заказчика, снятой заранее |
| «это же тестовый пример» | испытания ходят тем же путём, что человек; в протоколе указан экземпляр |
| «у вас не всё сделано» | раздел о состоянии функций и раздел об отступлениях — названы раньше, чем спросили |

## Чего не делать

* **не подгонять испытание под реализацию.** Испытание проверяет требование задания.
  Если требование не выполняется — исход «не пройдено», а не переформулировка требования;
* **не прятать «частично» в примечание.** Отдельный исход, отдельная строка итога;
* **не запускать приёмку впервые в день приёмки.** Прогонщик должен отработать
  минимум трижды до этого, на разных экземплярах.
