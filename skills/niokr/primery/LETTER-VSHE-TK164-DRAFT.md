математики им. С.Л. Соболева СО РАН; публикации: IEEE SIBIRCON 2024,
MDPI Mathematics 2024 Q1, DOI 10.3390/math12213429).

    Проект POLINOM подготовил маппинг 26 правил методологии Sigma
на подхарактеристики модели качества систем искусственного интеллекта
по ГОСТ Р 59898—2021. Цель маппинга — обеспечить применение POLINOM
как инструмента-источника метрик m_i для интегральной оценки качества
по формуле (8) §7.2.2.4 стандарта. В составе маппинга:

    - сопоставление 26 правил методологии Sigma с восемью
      подхарактеристиками §8 стандарта (Time Behaviour, Resource
      Utilization, Capacity, Maturity, Fault Tolerance, Robustness,
      Analysability, Compliance);
    - шкала нормирования значений метрик согласно требованиям
      §7.2.2.3;
    - предложение базовых значений и допустимых отклонений согласно
      формуле (2) §7.1.3.3, с распределением по трём уровням
      качества;
    - предложение весовых коэффициентов для всех трёх уровней
      свёртки (формулы 4, 6, 8 §7.2.2.4);
    - обоснование позиционирования POLINOM как закрывающего
      требования §7.2.1.2 (различие тестовой и эксплуатационной
      среды) через статическую классификацию кода.

    Просим Вас или назначенного Вами эксперта рассмотреть прилагаемые
документы и дать заключение по двум вопросам:

    1. Корректна ли по букве стандарта формулировка claim'а в §1.3
       маппинга («POLINOM — инструмент-источник метрик m_i для
       интегральной оценки качества систем искусственного интеллекта
       по формуле (8) §7.2.2.4 ГОСТ Р 59898—2021 в подмножестве
       подхарактеристик …»)?

    2. Корректны ли предложенные весовые коэффициенты в §5
       маппинга — как принципиальная конструкция (трёхуровневая
       свёртка с нормированием) и как численные значения по
       умолчанию (предоставляются как стартовая точка для
       последующей калибровки на конкретных СИИ)?

отдельного запроса не направляется.

    Просим Вашего внимания к следующим обстоятельствам:

    - проект POLINOM является академически-индустриальной инициативой
      на стыке Института математики СО РАН (правообладатель

    - подтверждение корректности маппинга экспертами разработки ГОСТ

## 3. Что делать при разных типах ответа

### 3.1 Положительный ответ с принятием маппинга в текущем виде

→ Финализировать `SIGMA-AI-QUALITY-MAPPING.md` v1.0 → v1.0-approved. Запустить Track A2-A4. Снять паузу проекта.

### 3.2 Положительный ответ с замечаниями по §1.3 / §5

→ Скорректировать маппинг по замечаниям. Перепроверить с ТК 164 / экспертом, что замечания учтены. Финализировать v1.0-approved. Снять паузу.

### 3.3 Нейтральный ответ («рассмотрите вопрос дополнительно с …»)

→ Перенаправить запрос рекомендованным экспертам. Параллельно — двигаться по запасному каналу (ИСП РАН, см. [`PROJECT-STATUS-GOST-TRACK-2026-05-29.md`](PROJECT-STATUS-GOST-TRACK-2026-05-29.md) §3.2).

### 3.4 Отрицательный ответ / отсутствие ответа в течение 4 недель

→ Запустить запасной канал через ИСП РАН (академический мост через ИМ СО РАН). Один отказ или молчание ТК 164 не убивает проект; они авторитет, но не монополист.
