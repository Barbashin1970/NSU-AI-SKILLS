# SKICODING — текст и код через один

> **Паттерн «ски-кодинг»**: текстовые и кодовые шаги чередуются, как лыжные следы, —
> левая, правая, левая, правая. Каждый шаг оставляет **проверяемый артефакт** (документ,
> коммит, проверку), который можно показать пальцем и сверить с предыдущим. Одиночный
> прыжок в код без разбора не катит с горы — он падает; одиночный документ без
> реализации замерзает и тонет в снегу. Темп держит только чередование.

Паттерн сформулирован в проекте РАГРАФ 23.05.2026 по факту восьми с лишним итераций
работы соло-разработчика с большой моделью; здесь он обобщён и дополнен режимом
интервью и связкой с комплектом документации по ЕСПД (`gost-19`).

## Два капкана, между которыми идёт паттерн

| Капкан | Как выглядит | Через неделю |
|---|---|---|
| **Гонка кода** | модель пишет код, человек принимает, документов нет | пять несовместимых решений, и никто не помнит, почему так |
| **Паралич документов** | написано четыре тысячи строк текста, в коде ничего | текст устарел и утонул в черновиках |

Ски-кодинг — компромисс: **каждый текстовый шаг кончается списком конкретных правок,
каждый кодовый — актуализацией текста.** Пропустили шаг — следы на снегу пропали,
и через три итерации к началу не вернуться.

## Цикл итерации: шесть шагов

Нечётные — текст, чётные — код.

| Шаг | Что | Артефакт |
|---|---|---|
| **1** (текст) | **Разбор**: что есть, чего не хватает, что закрываем, что откладываем | `docs/<ТЕМА>-RAZBOR.md`: сводка на 5–7 пунктов, схема, таблица «разрыв → важность → фаза», метрика «до», раздел «чего не делаем сейчас» |
| **2** (код) | **Реализация фаз** — по одному пункту таблицы за фазу | коммиты с пометкой фазы; после каждой изделие остаётся рабочим |
| **3** (текст) | **Актуализация документов**, которых коснулись фазы | правки в `docs/`; правка кода без правки документа — долг, и он идёт в бэклог |
| **4** (код) | **Новое, что выросло из шага 3** — то, чего не было в разборе | коммиты; чаще всего это интерфейс и удобство |
| **5** (текст) | **Бэклог отложенного** | записи в `docs/BEKLOG.md` с причиной и признаком возврата |
| **6** (код) | **Проверки** | по проверке на фазу; фаза без проверки — первый пункт следующего разбора |

Стрелка от шага 6 к шагу 1 — не «итерация закрыта», а «пересобрали карту перед
следующим спуском».

**Несущее правило шага 1:** разбор пишется **до** любых правок кода. Нашли по дороге
ошибку — записали строкой в таблицу и **не пошли чинить**. Отвлечение в код из разбора
и есть тот самый одиночный прыжок.

## Что этот навык добавляет к исходному паттерну

**Интервью в начале шага 1.** Разбор отвечает на вопрос «что есть». Документация нужна,
чтобы ответить на другой — **«что ожидалось»**, — а этого нет ни в коде, ни в разборе.
Поэтому перед разбором (а на новом проекте — вместо него) агент **спрашивает**:
по одному вопросу за раз, с вариантами ответа, ответы сразу в файл.
См. `references/intervyu.md`.

**Сценарии использования как узел.** Ожидание, записанное сценарием, становится
и требованием задания, и испытанием приёмки:

```
интервью → сценарий → требование задания (4.х) → испытание (И-х) → строка ведомости покрытия
```

Без сценариев непонятно, что ожидалось по заданию и что проверять в программе испытаний.
См. `references/uskeysy.md`.

**Шаг 3 ведёт к комплекту, а не к произвольным файлам.** Какой документ правится
при каком изменении — карта в `gost-19-komplekt`; что внутри каждого — `gost-19-dokumenty`.

## Фазы

Большой план режется на фазы: `A.1 / A.2 / B / C.1 / C.2`. Один уровень — семантическая
группа, подуровень — отдельный коммит.

**Фаза готова, когда верно всё:**

1. изделие запускается и работает (дешёвая проверка сборки/импорта прошла);
2. типы и стиль зелёные (если в проекте есть такие ворота);
3. есть хотя бы одна проверка, которая падает без этой фазы;
4. документы, которых фаза коснулась, обновлены;
5. в документе разбора пункт помечен закрытым — со ссылкой на коммит и проверку.

**Откладывать можно,** когда фаза требует внешних данных, ключей или живого источника;
когда она меняет работу человека так, что нужна отдельная итерация с заказчиком; когда
польза меньше затрат; когда она зависит от неоценённой фазы.

**Откладывать нельзя,** когда фаза закрывает логическую дыру (основной сценарий ложно
отвечает «всё хорошо»), когда это возврат ранее работавшего, и когда дело касается
безопасности.

Подробно — `references/cikl-i-shag.md`.

## Где что живёт

| Что | Где | Почему там |
|---|---|---|
| Сценарии использования | `docs/USE-CASES.md` | из них выводятся требования и испытания |
| Разбор темы | `docs/<ТЕМА>-RAZBOR.md` | живой документ прогресса: пункты закрываются со ссылкой на коммит |
| Отложенное | `docs/BEKLOG.md` | рядом с кодом, правится тем же коммитом, виден агенту и на ревью |
| Решения по архитектуре | раздел «Решения» пояснительной записки + короткая запись в день принятия | решение без обстоятельства — не решение, а предпочтение |
| Ограничения и отказы | раздел «Чего изделие не делает» | объявленное заранее — решение, объявленное в конце — оправдание |

## Комплект пишется не разом

Документы заводятся рано и растут: пояснительная записка — в первый день (сразу
с разделами решений и ограничений), описание программы — когда появился алгоритм,
руководства — когда есть чем пользоваться, программа испытаний — когда есть что
испытывать, опись и спецификация — в конце.

Пустой документ с честной пометкой «раздел не написан» лучше отсутствующего: у него
есть место, куда класть.

## Режим «готовый проект»

Код есть, документов нет. Разом такой комплект не пишется — только по одному документу
за проход, с чтением человеком между проходами:

```
инвентаризация → интервью → сценарии → задание → описание программы →
интервью о решениях → пояснительная записка → руководства → ПМИ → опись → спецификация
```

`references/gotovyy-proekt.md`.

## Чего не делаем

| Не делаем | Почему | Вместо |
|---|---|---|
| прыгаем в код без разбора | через две итерации не помним, что чинили | шаг 1 |
| пишем тысячи строк текста без кода | текст устареет за неделю | шаг 2 |
| правим большой устаревший документ по месту | диффы непредсказуемы, история «как думали раньше» теряется | переписать заново, `references/perepisat-dokument.md` |
| откладываем фазу «потому что сложно» | через три итерации забыли | причина в одном предложении, иначе фаза недоразобрана |
| пишем проверки после сдачи | возврат ошибки уедет в основную ветку | шаг 6 внутри итерации |
| доверяем памяти без проверки | память врёт через две итерации | `references/disciplina-agenta.md` |
| один большой коммит «сделал всё» | невозможно просмотреть | фазы |
| выдаём догадку за требование | по документу потом принимают работу | «не выяснено» и вопрос человеку |
