# Оформление и печать

Документ, написанный в Markdown и живущий в репозитории, рано или поздно надо
**предъявить на бумаге или в PDF**. Здесь собрано то, что выясняется на этом шаге —
обычно поздно и болезненно.

## Требования, которые надо знать заранее

**[ГОСТ]** По 19.105-78 документ состоит из титульной части, информационной части
(**аннотация и содержание**), основной части и части регистрации изменений.
Аннотация и содержание — обязательные части, а не вступление.

**[ГОСТ]** 19.106-78 задаёт требования к документам, выполненным печатным способом:
поля, нумерацию листов, оформление иллюстраций и таблиц, а также то, что **в содержание
включаются номера страниц**. Последнее — самое неудобное требование при печати
из браузера, см. ниже.

**[практика]** Практический минимум оформления, который проходит нормоконтроль:

* каждый раздел — **с новой страницы**; аннотация и содержание — тоже;
* заголовки разделов прописными;
* поля, оставляющие место под подшивку слева;
* нумерация листов сквозная, внизу;
* подпись листа: обозначение документа, наименование, номер листа и всего листов.

## Печать из браузера: что работает

**[замер] 15–16.09.2026, Chrome 131+.**

| Приём | Состояние | Чем пользоваться |
|---|---|---|
| поля страницы `@page { margin: … }` | **работает** | размер A4 и поля задаются CSS |
| подпись листа `@page { @bottom-center { content: … counter(page) " / " counter(pages) } }` | **работает** в Chrome 131+ | своя подпись на каждом листе, текст не трогается |
| разрыв перед разделом `break-before: page` | **работает** | разделы с новой страницы |
| `target-counter()` — номер листа другого элемента | **не поддержан ни одним браузером** | номера листов в содержании автоматически не проставить |
| `string-set` — название текущего раздела в колонтитул | **не поддержан** | живой колонтитул с названием раздела недоступен |
| свой колонтитул через `position: fixed` | **ломается** | налезает на текст; не применять |

**Другие браузеры** поля страницы пока игнорируют: лист выйдет без подписи, текст
при этом не поедет. Комплект печатается из Chrome — так и написать рядом с кнопкой
печати.

## Две ловушки, которые портят готовый PDF

**1. Колонтитул браузера.** По умолчанию браузер печатает свой верх и низ страницы:
адрес `127.0.0.1:8137/...`, дату печати, заголовок вкладки. На сдаваемом документе это
выглядит как распечатка из интернета. **Выключается человеком** в диалоге печати
(«Верхние и нижние колонтитулы») — значит подсказка об этом обязана стоять рядом
с кнопкой печати, а не в документации.

**2. Имя сохраняемого файла.** Браузер берёт его из заголовка вкладки. Пока заголовок
один на весь просмотрщик, все сохранённые PDF называются одинаково — одиннадцать
неразличимых файлов в папке загрузок. Заголовок обязан собираться из имени документа,
обозначения и редакции; в имени — только дефис, без `·` и `/`
(`gost-19/references/oboznacheniya-i-redakcii.md`).

## Содержание с номерами листов

Требование **[ГОСТ]** есть, автоматики в браузере нет. Три пути:

| Путь | Цена | Когда выбирать |
|---|---|---|
| **Полумера: таблица с пустой колонкой «Стр.»** | ноль | комплект печатают один раз — номера вписываются ручкой по готовой распечатке |
| **Выгрузка в docx** (pandoc + референсный шаблон) | час-два | номера и оглавление делает текстовый процессор; нужен заказчику в docx |
| **Свой разбиватель на листы** | недели | только если комплект переиздаётся постоянно и печатается пачками |

Подробно о каждом — `references/soderzhanie-i-nomera-listov.md`.

## Что ещё ломается при печати

* **таблицы шире листа** — задать `table-layout: fixed`, уменьшить кегль в печати,
  длинные ячейки переносить по словам;
* **схемы** (mermaid и подобные) — проверять в печати отдельно: то, что читается
  на экране, на листе бывает нечитаемо. Кегль подписей задавать явно;
* **тёмная тема** — печать обязана быть чёрным по белому независимо от темы браузера
  (`color-scheme: light !important` и явные цвета);
* **горизонтальные черты перед заголовками** — на экране разделяют, на листе
  дублируют разрыв страницы и выглядят мусором.
