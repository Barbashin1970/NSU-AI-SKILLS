## 1. Назначение программы

«LEYKA» — веб-система управления проектами Центра искусственного интеллекта НГУ (ЦИИ НГУ), разработанная для:

- планирования и отслеживания работ по проектам с индустриальными партнёрами и грантодателями;
- сбора и учёта фактов достижений по **11 показателям Приложения №2 Правил экспертизы** Минэкономразвития (публикации Q1, патенты, внедрения, датасеты и т.д.);
- представления директору центра **живого табло KPI** с прогрессом на выбранный отчётный год;
- ведения обязательной проектной документации по ЕСПД и ГОСТ 34 с поддержкой drag-and-drop загрузки файлов.

**Производственный адрес системы:** https://leyka-nsu.vercel.app  
**API-документация:** https://leyka-production.up.railway.app/docs  
**Текущая версия:** 0.2.0 (отображается при наведении на логотип «LEYKA» в шапке сайдбара)

## 2. Условия выполнения программы

### 2.1 Технические требования к рабочему месту оператора

| Компонент | Минимальные требования |
|---|---|
| Браузер | Google Chrome ≥ 120, Mozilla Firefox ≥ 120, Safari ≥ 17, Microsoft Edge ≥ 120 |
| Интернет-соединение | Не менее 1 Мбит/с для работы UI; не менее 5 Мбит/с для загрузки файлов |
| Разрешение экрана | Не менее 1280 × 720 пикселей |
| JavaScript | Обязателен, включён по умолчанию во всех современных браузерах |
| Cookies | HttpOnly cookie должны быть разрешены для домена `leyka-nsu.vercel.app` |
| Мобильные устройства | Поддерживается адаптивный режим (планшеты ≥ 768px) |

### 2.2 Учётная запись

Для работы в системе необходима активная учётная запись, созданная администратором или полученная по ссылке-приглашению. Вход осуществляется через:
- **OAuth Mail.ru** — корпоративный или личный аккаунт Mail.ru;
- **OAuth Google** — корпоративный или личный аккаунт Google;
- **резервный вход по логину и паролю** — email + пароль, доступен на том же экране входа в виде дополнительной формы; используется только администратором (`ROOT_EMAIL` / `ROOT_PASSWORD` из настроек сервера) на случай недоступности OAuth-провайдеров.

## 3. Выполнение программы

### 3.1 Вход в систему

**Через OAuth (рекомендуется):**

1. Открыть в браузере адрес https://leyka-nsu.vercel.app — загрузится экран входа.
2. Нажать кнопку **«Войти через Mail.ru»** или **«Войти через Google»**.
3. В открывшемся окне провайдера ввести учётные данные и подтвердить авторизацию.
4. После успешной аутентификации браузер перенаправит на главный экран системы.

**Через резервный локальный вход (для администратора):**

1. Открыть в браузере главный адрес https://leyka-nsu.vercel.app — на том же экране входа под кнопками OAuth-провайдеров расположена форма «Email + Пароль».
2. Ввести корпоративный email и пароль администратора (`ROOT_EMAIL` / `ROOT_PASSWORD`).
3. Нажать **«Войти»**.

**Выход из системы:**

Нажать на аватар / инициал в правом верхнем углу → раскрыть меню профиля → внизу слева кнопка **«Выйти»**. Сессионная cookie очищается немедленно.

> **Примечание.** Сессия действительна 7 суток. По истечении сессии система автоматически перенаправит на экран входа.

### 3.3 Управление заказчиками (партнёрами)

**Создание партнёра** (только администратор):

1. В нижней части сайдбара нажать **«+ Заказчик»**.
2. Ввести название (обязательно), выбрать цвет инициала из 8-цветной палитры.
3. Установить видимость:
   - **Закрытый** (`private`, по умолчанию) — виден только участникам проектов + администратору;
   - **Открытый** (`public`) — виден всем сотрудникам центра.
4. Нажать **«Создать»**.

**Редактирование:** Кнопка ⚙ на карточке партнёра → изменить название, цвет, видимость.

**Удаление** (только администратор): Кнопка ⚙ → **«Удалить»**. Каскадно удаляются все проекты и задачи партнёра. Операция необратима.

### 3.4 Управление проектами

**Создание проекта:**

1. В карточке партнёра нажать **«+ Добавить проект»**.
2. Ввести название проекта (обязательно), при необходимости — бюджет, дедлайн, описание.
3. Выбрать стадию (`presale` по умолчанию).
4. Нажать **«Создать»**.

**Стадии жизненного цикла проекта:**

| Стадия | Описание |
|---|---|
| `presale` | Пресейл, бюджет = 0, идут переговоры |
| `active` | Проект активен, ведётся разработка |
| `paused` | Временно приостановлен |
| `completed` | Завершён, передан заказчику |
| `archived` | Архивирован, только чтение |

Смена стадии: вкладка **«Настройки»** проекта → поле «Стадия» → сохранить.

**Вкладки проекта:**

| Вкладка | Назначение |
|---|---|
| 📋 **Доска** | Kanban-доска с задачами |
| 👥 **Участники** | Состав команды и роли |
| 📁 **Доки** | Чек-лист обязательной документации |
| 📊 **KPI** | Обязательства и факты достижений |
| ⚙ **Настройки** | Параметры проекта (бюджет, стадия, видимость) |

**Видимость проекта** (только администратор): вкладка «Настройки» → поле «Видимость»:
- `private` — только участники + администратор;
- `public` — все сотрудники центра;
- `demo` — все, включая новых сотрудников без проектов (для онбординга).

#### 3.4.1 Шаблоны быстрого наполнения проекта задачами

Чтобы не создавать вручную типовые задачи каждого нового проекта, в карточке настроек проекта (вкладка **«⚙ Настройки»** → секция **«✨ Шаблоны быстрого наполнения»**) доступны два шаблона:

| Шаблон | Что создаёт | Когда использовать |
|---|---|---|
| **Аналитика: старт работы с заказчиком до ТЗ** | 4 задачи + setup-задача на менеджера, ~4 недели | На пресейл-проектах: интервью с клиентом, бизнес-анализ, трендвотчинг, черновик ТЗ. |
| **Разработка: полный цикл** | 11 задач + setup-задача, ~12 недель | На активных проектах разработки: НИР → ТЗ → разработка → ПМИ → сдача → сопровождение → отчётность. |

**Условия для активации кнопок:**

- Доступно администратору и менеджеру проекта (право `can_edit_project`).
- В проекте должен быть участник с ролью **«Менеджер»** — иначе кнопки заблокированы и появляется подсказка: «Назначьте менеджера в проекте и укажите сроки реализации проекта в этой карточке».

**Расчёт сроков задач:**

- Если у проекта заданы и **дата старта**, и **дата завершения** — задачи распределяются равномерно по этому диапазону (последняя задача = дата завершения).
- Если одна из дат не задана — сроки рассчитываются от сегодняшнего дня по неделе на каждую задачу.
- Setup-задача всегда на сегодня (менеджер должен расставить ответственных как можно раньше).

**Что происходит после нажатия:**

1. В проекте создаются N задач со статусом «Входящие», без назначенных исполнителей. Сроки и стадия указаны в описании каждой задачи.
2. Setup-задача «Расставить ответственных по задачам шаблона» назначается на менеджера проекта (статус «В работе», приоритет «Важно»).
3. В setup-задаче автоматически создаётся комментарий с упоминанием менеджера через @ — он попадает в раздел **«Сообщения»** менеджера на вкладку **«Для меня»**.
4. Менеджер открывает каждую задачу шаблона, проверяет описание (содержит цель, чек-лист «На что обратить внимание», ожидаемый артефакт), при необходимости корректирует срок и назначает ответственного.

**Содержание задач шаблонов:**

Описания задач написаны под профиль ЦИИ НГУ — разработка программного обеспечения с ИИ-решением (модель, алгоритм, агент) в основе. Для каждой задачи указаны:
- **Цель** — зачем она нужна;
- **На что обратить внимание** — чек-лист из 5-8 пунктов с фокусом на специфике ИИ (данные, метрики качества модели, риски деградации, объяснимость, безопасность контура);
- **Артефакт** — что должно появиться в задаче на момент закрытия (отчёт, документ, ссылка на репозиторий и т.п.).

**Пример сценария «новый пресейл»:**

1. Аналитик (или менеджер) создаёт проект из карточки заказчика, указывает планируемые даты пресейла.
2. Менеджер сам себе ставит роль «Менеджер» в новом проекте.
3. В настройках проекта нажимает «**Аналитика: старт работы с заказчиком до ТЗ**».
4. Получает 5 готовых задач с разнесёнными сроками и видит уведомление в «Сообщениях».
5. Открывает setup-задачу, проходит по списку созданных задач, назначает на участников команды, корректирует тексты под конкретного клиента.

#### 3.4.2 Отчёт по проекту за период

В вкладке **«⚙ Настройки»** проекта → секция **«📄 Отчёт по проекту за период»** доступна простая выгрузка отчёта по закрытым задачам за выбранный период. Функция предназначена для предъявления заказчику / сдачи в бухгалтерию НГУ / отправки отчёта по гранту.

**Параметры:**

- **Период**: даты «С» и «По» (включительно). Кнопки-пресеты: «Текущий квартал», «Прошлый квартал», «Год».
- **Формат** (три кнопки):
  - **TXT** — обычный текст без спецсимволов. Для тех, кто копирует отчёт в Word / письмо без обработки.
  - **MD** (Markdown) — для правки в Typora / Obsidian / VS Code, последующей конвертации в DOCX или PDF через Pandoc.
  - **HTML** — открывается в новой вкладке браузера. **Cmd/Ctrl + P** → «Сохранить как PDF» — самый быстрый способ получить готовый PDF без установки чего-либо.

**Что попадает в отчёт:**

| Раздел | Содержимое |
|---|---|
| Шапка | Название проекта, заказчик, период, дата формирования, контактное лицо (менеджер). |
| Сводка | Закрыто задач за период, распределение по приоритетам и условным этапам. |
| Условные этапы | Задачи разбиваются на 3 группы по дате заведения: «Аналитика и исследование» (первая треть), «Разработка» (средняя), «Тестирование и сдача» (последняя треть). Если задач меньше 3 — одна группа «Работы за период». |
| Карточка задачи | Заголовок, ответственный, даты создания и завершения, приоритет, описание (без префикса «📋 Стадия:»), критерий выполнения, ссылки-доказательства из KPI-фактов. |
| Выполнение KPI центра | Таблица «План центра / Обязательство проекта / Факт за период / Статус» — появляется, если у проекта есть KPI-обязательства. |

**Доступ:** любой участник проекта может скачать отчёт.

**Сценарий «отчёт за квартал в бухгалтерию»:**

1. Менеджер открывает проект → «⚙ Настройки» → секция отчёта.
2. Жмёт пресет «Прошлый квартал».
3. Жмёт «**🖨 Открыть для печати (HTML)**» → открывается оформленный отчёт в новой вкладке браузера.
4. **Cmd/Ctrl + P** → «Сохранить как PDF» → готово, файл можно нести в бухгалтерию.

**Сценарий «отчёт нужно поправить под МинЭк»:**

1. Жмёт «**📥 Скачать MD**» → получает Markdown-файл `report-...md`.
2. Открывает в Typora / Obsidian / любом MD-редакторе.
3. Удаляет лишние разделы (например, внутренние комментарии команды), переписывает формулировки под официальный стиль.
4. Конвертирует в DOCX / PDF (Pandoc / экспорт из редактора) и отправляет.

> **Ограничения текущей версии (Phase A).** Условные этапы — эвристика по дате заведения задач, а не настоящие этапы проекта. В будущих версиях LEYKA появятся: реальные этапы (milestones), генерация Устава по форме НГУ, разрез бюджета по статьям КОСГУ, автогенерация листа согласования. См. [`docs/SKILL-PROJECT-CHARTER-AND-REPORTS.md`](SKILL-PROJECT-CHARTER-AND-REPORTS.md).

### 3.5 Работа с задачами (Kanban)

**Создание задачи:**

1. На доске проекта нажать **«+ Задача»** в любой колонке.
2. Ввести название (обязательно) и, при необходимости, критерий выполнения, описание, дедлайн.
3. Назначить исполнителя из списка участников проекта.
4. Выбрать тип задачи: 📝 **Задача** (по умолчанию), 💡 **Идея**, 🐛 **Баг**.
5. Нажать **«Создать»**.

> **Важно.** Поле «Автор» заполняется автоматически из текущей сессии и **не может быть изменено** — это защита статистики «чьи задачи закрываются».

**Статусы задачи (колонки Kanban):**

| № | Статус | Лейбл в UI | Описание |
|---|---|---|---|
| 1 | `inbox` | Входящие | Новая задача, не разобрана |
| 2 | `todo` | К работе | Разобрана, ждёт исполнителя |
| 3 | `in_progress` | В работе | Исполнитель начал работу |
| 4 | `waiting` | Ожидает | Ждём ответа заказчика, согласования или внешнего события |
| 5 | `review` | Проверка | Исполнитель закончил, нужна проверка коллегой/менеджером |
| 6 | `done` | Готово | Принято; учитывается в скорости закрытия |

Удалённой задачи (статус «отменена») в системе нет — задача либо переходит в `done`, либо удаляется кнопкой 🗑 (с подтверждением).

Перемещение задачи: **drag-and-drop** карточки между колонками. Альтернативный путь — открыть задачу в боковой панели (TaskDrawer) и сменить статус через выпадающий список.

> **Примечание.** При переводе в `done` без заполненного критерия выполнения откроется модальное окно с подтверждением: «Каким способом подтверждено выполнение?». Это сделано, чтобы факт закрытия был привязан к понятному артефакту (документ, акт, демонстрация, развёртывание и т.п.).

**Типы фильтров на доске:**

- Счётчики-фильтры над колонками: `Всего · 📝 Задача · 💡 Идея · 🐛 Баг` — клик фильтрует карточки по типу.

**Прикрепление ссылки к задаче (вложение):**

1. Открыть задачу → кнопка 📎 в шапке.
2. Вставить URL (Google Docs, Яндекс-диск, GitHub и т.д.).
3. Выбрать стадию документа из списка 12 стадий (см. Приложение В).
4. Нажать **«Прикрепить»**.

**Связанные задачи:**

- Кнопка-идентификатор UUID в шапке задачи копирует адрес задачи в буфер обмена.
- Вставить UUID в комментарии другой задачи — он автоматически превратится в кликабельный TaskChip.
- В разделе «Связанные задачи» (DrawerTaskLinks) можно вручную привязать задачи-источники и задачи-следствия.

### 3.6 Комментарии и двойные галочки

**Написать комментарий:**

1. Открыть задачу → поле ввода в нижней части ленты.
2. Написать текст. Для упоминания коллеги нажать кнопку **`@`** справа от поля → выбрать из списка команды.
3. Нажать **Enter** или кнопку **«Отправить»**.

**Индикация прочтения (двойные галочки):**

| Индикатор | Смысл |
|---|---|
| ✓ серая | Никто из команды пока не прочитал |
| ✓✓ синяя | Хотя бы один коллега прочитал |
| Hover на ✓✓ | Тултип: «Прочитали: Имя1, Имя2» |

- Пока не нажал «Прочитать всё», задача остаётся в фильтре «Для меня» / «Непрочитанные» в разделе «Сообщения».

**Редактирование и удаление:**

- Редактировать можно **только свой** комментарий: кнопка ✏ рядом с комментарием.
- Удалить — кнопка 🗑 рядом с комментарием.

### 3.6.1 Раздел «Сообщения» (Inbox)

Иконка **📥 Сообщения** в верхней части сайдбара ведёт в общий список задач, по которым идёт обсуждение. Три чипа-фильтра в шапке:

| Фильтр | Что показывает | Когда использовать |
|---|---|---|
| **Для меня** (по умолчанию) | Задачи, где меня **@-упомянули в непрочитанном комменте** ИЛИ **где я уже писал, и появились непрочитанные чужие комменты** | Сразу видно, где требуется реакция |
| **Непрочитанные** | Все задачи с хоть одним непрочитанным мной чужим комментом | Полный список «нужно прочитать» |
| **Все обсуждения** | Все задачи, где есть хотя бы один комментарий | Архив активности |

**Семантика «Для меня».** Чип ловит самый частый паттерн: «коллега ответил мне в треде без явного `@имя`». Если ты писал в задаче, и кто-то другой написал после тебя — задача попадает сюда автоматически. Прочитал (через «Прочитать всё» внутри задачи) — ушло из чипа.

**Виджет рисков KPI** (только для администратора центра). Над фильтрами появляется красная плашка «🔴 N KP под угрозой · ещё M под контролем», если на текущий квартал есть обязательства с риском срыва. Клик → переход на страницу «Прогноз».

### 3.7 Документация проекта (чек-лист)

Вкладка **«Доки»** в проекте содержит персональный чек-лист по 12 стадиям жизненного цикла (полный каталог — Приложение В).

**Включение слота:**

1. Найти нужный слот в списке стадий.
2. Нажать **«✓ Включить»** — слот станет активным и войдёт в подсчёт.

**Добавление ссылки к слоту:**

1. Раскрыть включённый слот → нажать **«➕ Ссылка»**.
2. Ввести URL документа и название.
3. Нажать **«Сохранить»**.

**Загрузка файла через drag-and-drop:**

1. Перетащить файл (PDF, DOCX, XLSX, PPTX, PNG, JPG, MD, до **15 МБ**) на область стадии в чек-листе.
2. Появится янтарный чип «грузится N%» с прогресс-баром.
3. После загрузки файл сохраняется в Google Drive центра под подпапкой `LEYKA-Temp/<имя проекта>/` и становится доступным по ссылке.
4. Чип превращается в документ с бейджем **«🕒 30 дней»** — файл хранится временно, следует скопировать в постоянный Drive.
5. При ошибке чип краснеет с текстом ошибки и кнопкой **«↻ Повторить»**.

> **Примечание.** Если Google Drive не настроен администратором, drag-and-drop недоступен (ответ 503 «загрузка временно недоступна»). Остальные функции чек-листа работают.

**Отключение слота:**

Навести курсор на слот → нажать **`×`** («убрать из чек-листа»). Слот становится приглушённым и не учитывается в счётчике. Восстановить — кнопкой «✓ Включить».

**Счётчик прогресса:**

В шапке вкладки отображается прогресс-бар: `закрыто N/M · K не выбрано`. Цвет бара: красный (< 30%), янтарный (30–70%), зелёный (≥ 70%).

### 3.8 KPI центра

#### 3.8.1 Страница «KPI центра» (для директора/администратора)

1. В сайдбаре нажать **«📊 KPI центра»**.
2. Выбрать **год** в селекторе (по умолчанию — текущий).
3. Отобразится сетка 11 плиток — по одной на каждую метрику Минэкономразвития.

**Каждая плитка** — высотой ~110px, состоит из:
- **«Корона года»** (тонкая полоса 6px сверху) — суммарный статус года к этому моменту. Толерантна к смещению работы между кварталами: если план был на Q2, факт случился в Q3 — корона к концу Q3 будет зелёной.
- **Стопка из 4 слоёв Q1–Q4** (Q1 снизу, Q4 сверху) — статус каждого квартала отдельно. Цвет каждого слоя — по тому же правилу процентов, что и тон плитки в целом.
- **Тон рамки плитки** — годовой прогресс (см. таблицу ниже), для быстрого worst-case-индикатора.

**Цвета (легенда едина для коронки, слоёв и рамки):**

| Цвет | Условие |
|---|---|
| 🔴 Красный | Прогресс < 30% или прошлый квартал не выполнен |
| 🟠 Оранжевый | Прогресс 30–70% |
| 🟡 Жёлтый/Амбер | Прогресс 70–100% или текущий квартал «под контролем» |
| 🟢 Зелёный | Прогресс ≥ 100% (план выполнен) |
| 🟢 Тёмно-зелёный | Перевыполнение свыше 110% |
| 🔵 Голубой | Будущий квартал, план есть, время не наступило |
| ⚪ Серый | Плана не задано (на квартал или вообще на год) |

**Задать план на год:**

1. Нажать на строку метрики (например, `z-9` — статьи Q1).
2. В модалке найти секцию **«План по годам»**.
3. Напротив нужного года нажать **«+ задать»** → ввести число → Enter.
4. Дашборд обновляется немедленно: показываются «Взято проектами» и «Без обязательств».

#### 3.8.2 Обязательства проекта (для менеджера)

1. В проекте перейти на вкладку **«KPI»**.
2. Нажать **«+ Добавить обязательство»** → выбрать код метрики (`z-1`..`z-11`), ввести `target_value` (план), комментарий.
3. **Указать квартал-контрольную точку** (1, 2, 3, 4 или «без квартала») — например, «РИД (`z-4`) к Q3, потому что регистрация 2-3 месяца» / «ПО (`z-2`) к Q4». Без квартала — общий план до конца проекта.
4. **Указать год** (2024..2030, по умолчанию текущий, переключается стрелками `↑↓`). Год нужен для:
   - **многолетних обязательств** — «ДПО, 100 чел/квартал на 2025, 2026, 2027» = три отдельные строки;
   - **наполнения архива** — заведение фактов задним числом за 2024-2025 для отчётов и витрины прошлых лет.
5. Прогресс-бар обязательства обновляется автоматически по мере добавления фактов.

> **Дробление.** На одну метрику в проекте можно повесить либо одно «безквартальное» обязательство, либо до 4 квартальных в каждом году (Q1+Q2+Q3+Q4 × N лет). Например: «300 человек ДПО на 2026, по 100 каждый квартал». Дублировать пару `(метрика, квартал, год)` нельзя — повторный POST обновит существующую запись.

**Редактирование:** кнопка ✏ у обязательства → изменить `target_value`.  
**Удаление:** кнопка 🗑 у обязательства → подтвердить.

> **Бейдж года в строке обязательства.** Под кодом метрики (`z-9`) — пилюля с кварталом и годом: `Q3 26` (Q3 2026). Без квартала отображается просто год: `2026`. Hover показывает полную формулировку.

#### 3.8.4 Прогноз контрольных точек

Раздел **«📈 Прогноз»** в сайдбаре — оперативное управление рисками срыва KPI к концу квартала.

1. Выбрать **год** и **квартал** (Q1..Q4) сверху страницы.
2. Видны 4 плитки-сводки: Всего · 🟢 Выполнено · 🟡 Под контролем · 🔴 Риск срыва.
3. Таблица обязательств отсортирована по риску: самые опасные сверху. Колонки: риск, метрика, проект, прогресс (факт/план), срок (дней до конца квартала), стрелка к проекту.
4. Клик на строку → открывает проект на вкладке «KPI».

**Кому что видно:**
- Администратор центра — все обязательства всех проектов.
- Менеджер / член проекта — только свои проекты в общем прогнозе. На вкладке «KPI» в проекте есть отдельный баннер «Прогноз Q3: X выполнено, Y под контролем, Z рисков» — менеджер видит свои риски проактивно, без обращения к директору.

**Светофор риска** считается из плана метрики на квартал, накопленных фактов с начала года и оставшегося времени до конца квартала. Подробное правило — см. ARC.md §8.6.

#### 3.8.3 Факты достижений (KpiAchievement)

1. В проекте на вкладке **«KPI»** → нажать **«+ Факт»** у нужного обязательства.
2. Ввести заголовок (обязательно) и ссылку-доказательство (URL).
3. **Указать дату факта** (поле «Дата факта», по умолчанию — сегодня). Можно ставить **задним числом** (например, 2024-09-15 для статьи 2024 года) — это критично для наполнения архива и витрины прошлых лет. Дата определяет, в какой год и квартал засчитается достижение.
4. Для добавления нескольких доказательств к одному факту:
   - Раскрыть строку факта → **«доказательства N ▾»** → **«➕ добавить»** → URL + необязательный заголовок («Акт», «Договор», «Демо»).
   - Лимит: **до 10 доказательств** на один факт.
5. Нажать **«Сохранить»**.

> **Важно.** Закрытие задачи само по себе **не** двигает прогресс KPI. Менеджер или разработчик должен явно создать `KpiAchievement` через «+ Факт».

> **Backfill за 2024-25.** Чтобы наполнить архив и витрину центра прошлых лет:
> 1. Создать обязательство с нужным **годом** (например, «z-9 Q3 2024 = 1 статья»);
> 2. Нажать «+ Факт» → задать **дату факта** в 2024 году (например, 2024-09-15);
> 3. Прогресс обязательства закроется, факт появится в `kpi-summary?year=2024` и (после публикации) на витрине прошлого года.

### 3.9 Витрина достижений

Страница **«✨ Витрина центра»** в сайдбаре — публичный раздел для всех авторизованных пользователей, включая гостей без проектных членств.

**Публикация факта на витрину** (только администратор):

1. На странице «KPI центра» найти нужный факт в drill-down списке метрики.
2. Нажать кнопку **«✨ опубликовать»** у факта.
3. В палитре 7 типов выбрать тип артефакта (система автоматически предложит тип по домену URL: `arxiv.org` → 📄 статья, `github.com` → 💻 ПО и т.д.).

**Выбор маркетинговой ссылки:**

1. В drill-down раскрыть «доказательства N ▾» у опубликованного факта.
2. Нажать фиолетовый **radio-кружок** у нужного доказательства.
3. На витрине будет отображаться именно эта ссылка.

**Снять с витрины:** нажать цветную плашку **«✨ на витрине»** у факта → подтвердить.

**7 типов артефактов на витрине:**

| Прототип | 🧪 | Vercel/Netlify демо, Hugging Face Spaces |

### 3.10 Управление участниками и ролями

**Добавить участника в проект** (менеджер или администратор):

1. В проекте открыть вкладку **«Участники»**.
2. Нажать **«+ Добавить»** → выбрать пользователя из списка сотрудников.
3. Назначить **проектную роль** (определяет права в проекте, см. Приложение А).

**Матрица прав (только администратор):**

2. Отобразится таблица: 6 ролей × 12 флагов прав, сгруппированных по категориям:

> **Примечание.** Не-директор видит страницу «Мои права» в режиме только чтение — это поясняет, что именно доступно пользователю.

1. Нажать на аватар профиля → **«Профиль»**.
2. Изменить **отображаемое имя** («Как меня видят коллеги») — это имя показывается в `@`-упоминаниях, шапках задач, комментариях.
3. Нажать **«Сохранить»**.

> **Важно.** Email привязан к OAuth-аккаунту и не редактируется из UI.

### 3.12 Окно «О LEYKA» — справка по ролям

В системе предусмотрено справочное окно, объясняющее назначение программы и её пользу для каждой из ролей. Открыть его можно следующим способом:

1. Нажать на чип своего имени (аватар + имя) в правом верхнем углу — раскроется карточка профиля.
2. В нижней части карточки расположены две кнопки: слева — **«Выйти»**, справа — **«О LEYKA»**.
3. Нажать **«О LEYKA»** — справа откроется боковая панель с подробной информацией.

**Что внутри:**

- **Автоматически активная вкладка** соответствует роли пользователя:
  - администратор → 👑 «Директору центра»;
  - менеджер проекта → 📋 «Руководителю проекта»;
  - аналитик / дизайнер → 📊 «Аналитику · Дизайнеру»;
  - разработчик → 💻 «Разработчику»;
  - куратор / заказчик / наблюдатель → 🎓 «Куратору · Заказчику»;
  - гость без проектов → 🌧 «Зачем LEYKA» (вступление с описанием системы).
- Любую другую вкладку можно открыть кликом — это разрешено всем (полезно понять, что видят и могут делать коллеги в других ролях).
- В подвале панели — общая информация: «Зачем мы это делаем», техническая сводка («Что внутри»), ссылки на документацию и репозиторий.

**Закрытие панели:** клавиша `Esc`, клик по кнопке `×` в шапке панели или клик по затемнённой области слева.

> **Примечание.** Окно носит справочный характер и не содержит конфиденциальной информации (бюджеты, цены, экономия) — эти данные обсуждаются на отдельных рабочих презентациях.

### 3.13 Резервная копия данных

Программа предусматривает скачивание полной резервной копии базы данных в виде ZIP-архива. Это позволяет страховаться от утраты данных и при необходимости перенести систему на другую инфраструктуру.

**Кому доступно:**

| Действие | Кто может |
|---|---|
| Скачать резервную копию | Администратор центра + менеджер любого проекта (роль с правом «Редактировать проект») |
| Восстановить систему из резервной копии | Только администратор центра |

Менеджер проекта скачивает копию как страховку: если сервис когда-то перестанет работать, менеджер передаёт файл администратору, и тот восстанавливает систему. Сам менеджер восстановление не выполняет — это разрушительная операция, требующая прав администратора.

**Как открыть:**

1. Нажать на чип имени в правом верхнем углу — откроется карточка профиля.
2. В списке пунктов выбрать **«Резервная копия»** (иконка с цилиндром БД). Пункт виден только пользователям с правом доступа.
3. Откроется модальное окно «Резервная копия БД» с двумя секциями: **«Скачать»** и (для администратора) **«Восстановить из файла»**.

**Скачивание:**

1. В секции «Скачать резервную копию» нажать кнопку **«Скачать сейчас»**.
2. Браузер сохранит файл `leyka-backup-YYYY-MM-DD-HHMM.zip` в папку загрузок (имя содержит дату и время с точностью до минуты).
3. Файл рекомендуется хранить в надёжном месте: облачный диск (Я.Диск, Google Drive), внешний носитель, корпоративное хранилище.

**Что внутри архива:**

- `leyka.db` — атомарный снимок базы данных SQLite (создаётся через нативный SQLite-механизм Connection.backup, не блокирует работу системы во время скачивания).
- `manifest.json` — метаданные снимка: версия формата, версия приложения, дата создания (UTC), количество записей по основным таблицам (партнёры, проекты, задачи, комментарии, пользователи, материалы библиотеки знаний). Используется для идентификации архива и проверки совместимости.

**Восстановление (только администратор):**

1. В секции «Восстановить из файла» нажать **«Выбрать ZIP-файл»** и указать ранее сохранённую копию.
2. Нажать **«Восстановить»**.
3. Появится подтверждающее окно с предупреждением: «Заменить текущую БД на содержимое файла? Все изменения, сделанные после момента бэкапа, БУДУТ ПОТЕРЯНЫ». Подтвердить — **«ОК»**.
4. Система выполнит замену БД и сообщит об успешном восстановлении.
5. **После операции необходимо перезапустить серверный сервис** (на Railway — кнопка Restart в панели управления; на сервере НГУ — `sudo systemctl restart leyka-api`). Без перезапуска возможны временные сбои у пользователей, чьи запросы попали в момент замены.

**Откат от отката:**

При восстановлении старая база данных не удаляется, а сохраняется рядом с новой под именем `leyka.db.before-restore` в той же папке (на Railway — `/data/`, на сервере НГУ — `/var/lib/leyka/`). Это страховка на случай, если восстановление прошло из неправильного архива или потребовалось вернуть систему к состоянию «до восстановления».

Если после восстановления администратор не может зайти в систему (например, в восстановлённой БД нет его учётной записи), для отката используется **аварийный endpoint `POST /api/v1/backup/rollback`** — он работает БЕЗ авторизации, защищён секретным токеном из переменной окружения `BACKUP_ROLLBACK_TOKEN`. Открывается через Swagger UI бэкенда (`/docs`). Подробная процедура — в `LEYKA_InstallManual_GOST19.md` §6.7, блок «Откат от отката».

**Сценарий: переезд с Railway на сервер ЦИИ НГУ:**

1. На Railway-инсталляции скачать резервную копию (см. выше).
2. На целевом сервере развернуть LEYKA по руководству администратора (`LEYKA_InstallManual_GOST19.md`, раздел «Перенос данных с Railway»).
3. Зайти в новую инсталляцию под учётной записью администратора.
4. Открыть «Резервная копия» → «Восстановить из файла» → выбрать ZIP с Railway → подтвердить.
5. Перезапустить сервис: `sudo systemctl restart leyka-api`.
6. Проверить, что данные на месте (партнёры, проекты, задачи, комментарии, пользователи).

> **Примечание.** Сами учётные записи пользователей и их пароли восстанавливаются полностью. Однако HttpOnly-cookies сессий перестанут работать (cookie привязаны к секрету `JWT_SECRET`, который у новой инсталляции другой). Пользователям нужно будет пройти аутентификацию заново. Это поведение является штатным и обеспечивает безопасность переезда.

### 3.14 Мобильная версия и установка как приложения (PWA)

LEYKA — Progressive Web Application (PWA): после установки она открывается из иконки на главном экране телефона или Dock'е компьютера, работает в собственном окне без браузерного chrome (адресной строки и вкладок), показывает счётчик непрочитанных на иконке (Android и десктоп). Для установки и использования не требуется магазин приложений (App Store / Google Play).

#### 3.14.1 Поделиться адресом приложения через QR-код

**Сценарий.** Сотрудник рядом хочет открыть LEYKA на своём телефоне — не нужно диктовать адрес.

1. Открыть меню профиля (чип имени в правом верхнем углу) или, если ещё не выполнен вход, остаться на странице авторизации.
2. Нажать кнопку **«QR-код»** (иконка квадратного штрих-кода) в нижней панели меню профиля либо в нижней панели окна авторизации.
3. На весь экран откроется модальное окно с QR-кодом, содержащим адрес приложения.
4. Коллега наводит камеру телефона — открывается страница входа LEYKA. Дальше он входит через свой аккаунт Mail.ru / Google или присоединяется по приглашению менеджера.
5. Под QR-кодом дублируется текстовая ссылка и кнопка **«Скопировать ссылку»** — на случай, если камера не сработала.

#### 3.14.2 Установка LEYKA на главный экран телефона

**iOS (Safari):**

1. Открыть приложение в браузере Safari (другие браузеры на iOS не поддерживают установку).
2. Нажать кнопку «Поделиться» в нижней панели Safari (иконка квадрата со стрелкой вверх).
3. В списке действий пролистать и выбрать **«На экран „Домой"»**.
4. Подтвердить имя «LEYKA» и нажать **«Добавить»** в правом верхнем углу.
5. Иконка появится на главном экране. Запуск из иконки откроет LEYKA в полноэкранном режиме без адресной строки Safari.

**Android (Chrome):**

1. Открыть приложение в Chrome.
2. Через несколько секунд внизу экрана появится баннер **«Добавить LEYKA на главный экран»**, либо открыть меню Chrome (три точки) и выбрать **«Установить приложение»** / **«Установить LEYKA»**.
3. Нажать **«Установить»**.
4. Иконка появится в списке приложений и на главном экране. На иконке отображается счётчик непрочитанных сообщений (если поддерживается лаунчером устройства).

#### 3.14.3 Установка LEYKA на компьютер (Chrome / Edge / Safari)

**Сценарий.** Открывать LEYKA в отдельном окне без вкладок и закладок браузера, иметь иконку в Dock'е или меню «Пуск», получать счётчик непрочитанных на иконке приложения.

1. Открыть https://leyka-nsu.vercel.app в Chrome, Edge или Safari (macOS 16.4+).
2. В правой части адресной строки появится иконка установки — обычно квадрат со стрелкой вниз или подсказка **«Установить LEYKA»**.
3. Нажать на иконку → **«Установить»**.
4. LEYKA откроется как отдельное приложение: своё окно, своя иконка в Dock (macOS) / в панели задач (Windows).
5. Счётчик непрочитанных сообщений будет появляться на иконке (необходимо, чтобы приложение было запущено или недавно открыто).

> Установка не дублирует данные — это та же самая система, просто в собственной оболочке без браузерного chrome'а. Все cookie и сессии общие с браузером.

#### 3.14.4 Обновление до новой версии (синий баннер снизу экрана)

После установки PWA, при выходе новой версии LEYKA:

1. В нижней части экрана появится синий баннер: **«Доступна новая версия LEYKA — обновить?»** с иконкой обновления.
2. Если в данный момент идёт работа (открыт черновик комментария, заполняется задача) — баннер можно проигнорировать, он не торопит. Версия применится при следующем удобном моменте.
3. Когда удобно — нажать **«Обновить»**. Приложение перезагрузится в новую версию за 1–2 секунды.
4. Если баннер закрыли крестиком — он появится снова при следующем открытии приложения, пока обновление не будет применено.

> Обновление никогда не происходит автоматически — это намеренно. Иначе принудительная перезагрузка во время написания длинного комментария или заполнения KPI могла бы привести к потере данных формы.

#### 3.14.5 Особенности мобильной версии

| Раздел / функция | Поведение на мобильном |
|---|---|
| Канбан-доска проекта | Заменяется заглушкой «Открой на десктопе» — drag-and-drop неудобен на сенсоре. Для просмотра задач использовать раздел «Сообщения» (Inbox). |
| Боковое меню (заказчики/проекты) | Свёрнуто по умолчанию. Клик по аватарке заказчика открывает его проект сразу (если проект один) или карточку заказчика (если несколько). Полное меню — через кнопку с шевронами. |
| Окно задачи | Описание сверху (компактно, со своим скроллом), лента переписки снизу с композером. Удаление задачи скрыто — выполнить можно только с десктопа. |
| Чипы фильтров «Сообщений» | Показаны только иконки (👁 «Для меня», 👁⃠ «Непрочитанные», Σ «Все») — для экономии места. |
| Чипы сводки на странице «Прогноз» | Только иконки + цифры (Σ всего, ✅ выполнено, 👁 под контролем, 🚨 риск срыва). Полные подписи доступны при долгом нажатии. |
| Кнопка полноэкранного режима | Скрыта — не нужна, PWA уже в standalone-окне. |

#### 3.14.6 Масштабирование текста (увеличение для чтения)

В установленной PWA жест «развести два пальца» для увеличения шрифта работает непредсказуемо: сразу после открытия задачи он заблокирован, после фокуса в поле ввода — разблокирован, после повторного открытия — снова заблокирован. Это штатное поведение iOS Safari для приложений с фиксированной разметкой (как Telegram Web, Linear, Notion на телефоне) — не ошибка LEYKA.

**Рекомендация для пользователей с проблемами зрения.** Использовать системную настройку увеличения шрифта:

- **iOS:** Настройки → Универсальный доступ → Дисплей и размер текста → Увеличенный текст. Перетянуть ползунок до удобного размера. Настройка применяется ко всем приложениям, включая LEYKA-PWA.
- **Android:** Настройки → Специальные возможности → Размер шрифта. Перетянуть ползунок.
- **Десктоп:** в браузере — Cmd/Ctrl + «+» / «−». В установленной PWA — Cmd/Ctrl + «+» / «−» в меню окна (правый верхний угол PWA).

## 4. Сообщения оператору

### 4.1 Сообщения об ошибках

| Сообщение | Причина | Действие |
|---|---|---|
| `OAuth state mismatch — попробуй войти ещё раз` | Истёк или не сохранился state-cookie OAuth | Закрыть вкладку, открыть новую, повторить вход |
| `503 — загрузка временно недоступна` | Google Drive не настроен администратором | Добавить ссылку вручную; обратиться к администратору |
| `Нет доступа (403)` | Нет прав на объект или не состоит участником | Попросить менеджера добавить в проект |
| `Не найдено (404)` | Объект удалён или UUID неверный | Обновить страницу, проверить ссылку |
| `Ошибка валидации (422)` | Неверные данные в форме | Проверить обязательные поля, исправить значения |
| `Сервер временно недоступен (503/502)` | Railway перезапускается | Подождать 30–60 с, обновить страницу |
